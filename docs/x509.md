# MONGODB-X509 authentication

Bongo implements MongoDB's MONGODB-X509 authentication command and validates X.509 connection-string requirements.

X.509 authentication always uses the `$external` authentication database, does not accept a password, requires TLS, and requires client-certificate configuration. The username is optional on modern MongoDB deployments; when omitted, MongoDB derives the identity from the presented client certificate.

```zig
var options = try bongo.parseConnectionOptions(
    allocator,
    "mongodb://db.example/?authMechanism=MONGODB-X509&tls=true&tlsCertificateKeyFile=%2Fsecure%2Fclient.pem",
);
defer options.deinit();

const credentials = try bongo.X509Credentials.fromConnectionOptions(options);
```

Once a mutual-TLS transport has presented the configured client certificate, authenticate it with:

```zig
try bongo.authenticateX509(
    &secure_transport,
    allocator,
    credentials.username,
);
```

The authentication function is generic over any request-capable secure transport because the MongoDB `authenticate` command is independent of the TLS implementation.

## Zig 0.16 TLS limitation

Bongo v0.3 does not ship a built-in TLS transport. Release validation showed that Zig 0.16's `std.crypto.tls.Client` cannot complete the client-certificate request path used by a TLS-enabled MongoDB server, and it does not expose the client-certificate/private-key support required for MONGODB-X509.

The protocol and configuration layers remain available, but end-to-end MONGODB-X509 requires a secure transport that can complete MongoDB's TLS handshake and present the configured client certificate. Runtime TLS support remains tracked separately by BONGO-0042.
