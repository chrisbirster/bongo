# Bongo v0.3 hardening audit

BONGO-0101 audits the exact RuntimeClient path used by Deez against the frozen v0.3.0 baseline. Findings are fixed on focused branches and merged into `dev` only after the branch is ready for the full repository test gate.

## Completed hardening

- **HIGH — failed pooled transports were returned to the pool.** Fixed by discarding any transport whose request fails and centralizing checkin ownership.
- **HIGH — pool checkin failure could double-deinit a transport.** Fixed by making checkin own cleanup.
- **HIGH — selected-server failover could double-deinit the stale transport.** Fixed by explicit optional ownership transfer.
- **HIGH — an unreachable remembered server prevented failover to another configured seed.** Fixed by re-running writable-server selection when opening or probing the remembered server fails. Runtime replica-set coverage forces the selected index to an unreachable seed while a healthy seed remains available.

## Validation gate

The canonical local gate is:

```bash
make test
```

It provisions the standalone, TLS, and replica-set MongoDB fixtures before running the unit, integration, TLS, runtime, and Deez-readiness suites.
